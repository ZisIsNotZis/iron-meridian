# Exhaustive audit of the 106 remaining design Markdown files

Audit date: 2026-08-27  
Scope: every Markdown file below design/ (106 files). Repository root Markdown and CONTEXT.md are outside the requested 106-file scope.  
Rule: no Markdown may remain canonical.  
Non-mutating checks: node tools/check_content.mjs --coverage reported markdown_files=106 and unmapped=28; node tools/check_content.mjs passed 187 YAML content files.

## Executive result

The current YAML corpus is structurally valid, but it is not a complete replacement for the Markdown corpus. Current YAML has typed homes for concrete factions, units, buildings, reusable profiles, four maps, four campaign missions, one scenario, nine recipes, one production queue, and four world characters. It does not yet have typed homes for most system contracts, product scope, platform protocols, development evidence, world background, faction registries, AI, progression, technology, objectives, or presentation contracts.

Classification:

- CO — concrete object already covered. The Markdown contains only a collection label/schema reminder; concrete values are already in current YAML/schema. It may be deleted after generated navigation is confirmed.
- IN — index/navigation needing a registry/index YAML. Links, roster membership, status, ordering, catalog meaning, or allow-list information would be lost.
- SY — global principle/system contract needing a typed YAML object/schema. Cross-object rules, protocols, product contracts, or system policies would be lost.
- NA — narrative/background needing structured YAML fields. Setting, faction, identity, political, or story material would be lost.
- IM — implementation/development note needing YAML. Delivery, test, release, persistence, package, or operational policy would be lost.

No row below means “safe to delete now.” CO means “no unique canonical game fact remains after checking the linked YAML”; every other class requires migration first.

## Current YAML/schema homes used in this audit

- Entity records: design/content/factions/**, selected by unit.yml, building.yml, or faction.yml.
- Reusable profile records: design/content/{armors,damages,locomotors,targetabilities,collisions,sensing,skills,statuses,weapons,production,recipes}/*.yml, selected by profile.yml.
- Maps, scenarios, campaigns: design/content/maps/*.yml, scenarios/*.yml, campaigns/*.yml with map.yml, scenario.yml, and campaign.yml.
- World characters: design/content/world/characters/*.yml with world_character.yml.
- Schema policy: design/schema/registry.yml and named properties in design/schema/*.yml.
- Existing entity YAML fields cover concrete stats, references, state/transition data, production, presentation, audio/FX, and named design prose. They do not automatically cover a roster index, a global rule, or a sentence about a faction’s narrative.
- Proposed paths below are destination paths, not edits made by this audit. “AMEND” means a named property or schema family must be added. No generic notes, metadata, comment, extra, or unrestricted prose field is proposed.
